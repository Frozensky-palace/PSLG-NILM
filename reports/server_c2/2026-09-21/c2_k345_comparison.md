## 2. 逐项判读

**k=5 直接排除（A5 门槛：无不可训练的极小状态）。**
状态 4 只有 2 个块，是聚类噪声而非物理状态；k=5 本质是 k=4 加一个退化态。
转移图里状态 4 的出入边各只有 1–2 条，无法支撑任何拼接或生成建模。

**k=3 把中功率与高功率合并，丢失了洗衣机的核心物理结构。**
k=3 的状态 0（1,608W/888s，时长差 x3.1）实际是 k=4 中
"1,018W/324s 过渡 + 1,866W/630s 加热" 两态的混合；只余 6 条转移边，
拼接结构表达能力不足。

**k=4 与物理统计 pilot 相互印证，且多分离出一个洗涤态。**
与 Phase A 的 physical-stats pilot（k=3）对比：

| 物理状态 | pilot（物理统计特征） | C2 k=4（DETSEC-PC 特征） |
|---|---|---|
| 中功率过渡 | 1,014W / 324s | 1,018W / 324s |
| 高功率加热 | 1,866W / 636s | 1,866W / 630s |
| 长时低功率 | 211W / 4,548s | 153W / 3,294s |
| 洗涤/漂洗中低功率 | （未分离，混在低功率内） | **397W / 1,266s（新增）** |

两套完全不同的特征在功率/时长上几乎一致的态上收敛（1,014→1,018W、
1,866→1,866W），说明这些是数据里的真实物理状态而非特征伪影；
DETSEC-PC 额外把洗涤段从长低功率中拆出。

**已知遗留风险（沿袭 A2 结论）**：k=4 的状态 1（长时低功率）时长 p10–p90
跨 10.7 倍，仍是最多模态的状态；B5 的持续时间建模必须显式处理它。

## 3. 冻结建议

**推荐：以 C2 k=4 作为状态库 v1 的正式候选**（`formal_candidate_detsec_pc`），
理由：结构可解释、无退化态、转移图（11 边）足以支撑 B2/B5 的顺序建模、
且与 pilot 物理结构交叉验证一致；与 Phase A 冻结的"k=4 首选"预判一致。

按协议，最终冻结前还有一道 validation 侧确认（"validation 只用于选 k"）：
用 Phase A 冻结的 B2-matched 策略（duration-only + 限长 [0.67,1.5]）在
validation CPU smoke 上对 C2-k4 库做一次选 k 复核。注意有一个**格式衔接工作**：
C2 状态库（state_inventory.csv + state_waveforms.npz）与 B2 构建器消费的
pilot 库格式不同，需要一个小适配器——这是 C3 B2 arm 开跑前的唯一本机待办。
