## 0. 摘要

围绕"基元状态生成+受约束拼接是否优于直接整段生成"这一核心问题，两周内完成了
Phase A/B 的全部本机基础、C1–C4 的全部服务器实验，以及 D/E 阶段五条生成路线的
本机开发与服务器生成（5/5 过双门）。目前最重要的科学结论来自 C4：**受约束基元
重组（B2-matched）随合成数据比例扩大单调改善且方差坍缩（r2.0 达 MAE 10.38±0.08），
而完整周期重放（B1）在 r2.0 退化**——这为生成路线立下了必须超越的基线。D/E 七臂
下游重训正在服务器排队执行。

## 3. 关键实验与结果

### 3.1 C1：服务器环境冻结（h104）

TensorFlow 2.18.1 与 torch 2.5.1+cu121 各自枚举到 RTX 3090 并通过前向/反向冒烟；
C1 冒烟阶梯（manifest→单测→CPU 读→双框架→8-cycle→短训→恢复→推理→复现）全部通过。
环境偏离已记录：pslg-detsec 补 PyWavelets；pslg-nilm 钉 torch==2.5.1。

### 3.2 C2：正式状态发现

493 个 train 周期全量 DETSEC-PC 状态发现，16 分钟完成。三套候选库结构对比如图 1：

![C2 k3/4/5 结构](figures/fig1_c2_k345_structure.png)

- **k=5 排除**：状态 4 仅 2 块/2 周期，退化不可训练；
- **k=3 排除**：中功率与高功率合并（1,608W/888s），丢失加热态语义，转移图仅 6 边；
- **k=4 与 pilot 物理结构交叉印证**（1,018W/324s、1,866W/630s 两态跨特征几乎一致），
  并新增 397W/1,266s 洗涤态，11 条转移边。

已知风险：状态 1（长时低功率）时长跨 10.7 倍，多模态——B5 的时长建模需显式处理。

### 3.3 M1：状态库 v1 冻结

![G-2 选 k 复核](figures/fig2_g2_k_check.png)

G-1 格式验证零代码通过（C2 库与 pilot 库 31 列逐列同构）；G-2 用冻结 B2-matched
策略对三库做 validation 复核，差异 ≤0.13W（噪声内）——validation 不构成偏好，
按结构证据冻结 **v1 = C2-detsec-k4**。所有 B3/B4/B5 生成均以 v1 为状态定义。

### 3.4 C3：B0/B1/B2 三臂对照（r0.5，3 seeds）

| 指标 | B0 无增强 | B1 周期重放 | B2-matched 基元拼接 |
|---|---|---|---|
| MAE (W) | 13.73±4.37 | 12.04±2.90 | **11.84±1.61** |
| F1 | 0.589 | 0.733 | 0.730 |

配对 bootstrap：B1>B0 在 3/3 seeds 一致（**此前"合成造成域偏移"的担忧被消除**）；
B2-matched 均值最优且方差最小，但与 B1 差 0.20W、逐 seed 方向翻转——
诚实表述是"相当且更稳"，还不能说"基元重组已胜过完整周期"。

### 3.5 C4：比例实验（核心结论）

![C4 比例曲线](figures/fig3_c4_ratio_curve.png)

| MAE (W) | r0.5 | r1.0 | r2.0 |
|---|---|---|---|
| B1 周期重放 | 12.04±2.90 | 10.14±0.79 | 11.99±2.59（退化） |
| B2-matched | 11.84±1.61 | 10.55±0.76 | **10.38±0.08** |

- **B2-matched 单调改善且方差坍缩**（±1.61 → ±0.08）：基元每次从 493 周期里
  重新选择与组合，信息量随比例增加；
- **B1 在 r2.0 退化**：同一批真实周期重复放置，边际收益转负；
- B2@r2.0 的 F1=0.789 为全部 15 组中最高；C3 中 B2 最差的 s73 在 r2.0 反转为
  B2 优势最大。

**结论：受约束基元重组可扩展、完整周期重放不可扩展。生成基线的对照线立为
B2-matched@r2.0（MAE 10.38 / F1 0.789）——B3/B4/B5 的 validation 必须优于这条线，
否则生成不如"多放几遍真实基元"。**

### 3.6 D/E：五条生成路线（5/5 过双门）

![D/E 双门](figures/fig4_de_gates.png)

| 路线 | 质量门 | 记忆审计 | 复制率 |
|---|---|---|---|
| B3-T 变换 | true | true | 0.992（定义属性：形变真实周期本就近邻；exact=0） |
| B3-V CVAE | true | true | 0.000 |
| B3-G WGAN | true | true | 0.000 |
| B3-D 扩散 | true | true | 0.000 |
| B4 基元拼接 | true | true | 0.004 |

B3-T 与神经路线的复制口径分开记录：前者近复制是方法定义（形变真实数据），
后者的门槛是 1%（实际 ≤0.4%）。扩散路线经三次修复后过门（见 §4）。

## 4. 开发中遇到的问题与解决（按发现顺序）

| # | 问题（阶段） | 根因 | 解决 |
|---|---|---|---|
| 1 | 服务器测试 97≠131（C0） | 第三方 `tests` 包遮蔽仓库包 | 加 `tests/__init__.py` + 导入回退 |
| 2 | 冻结文档自相矛盾（A） | 17/18 变体计数错误 | 修正为 18 全通过 |
| 3 | 训练/验证 MAE 不可比（C3 准备） | 评价样本集不同（monitor vs first-N） | predict 增 `--sample-source monitor`，重出指标 |
| 4 | smoke 记录旧 commit（C2） | 提交后未重跑 | 重跑并绑定当时 HEAD |
| 5 | pslg-detsec 缺 pywt（C1 服务器） | 环境文件漏列 | 补 PyWavelets（两环境） |
| 6 | torch 版本漂移 2.14+cu130（C1） | `torch>=2.4` 让 pip 从 PyPI 解析到未验证构建且 CUDA 初始化失败 | 钉 `torch==2.5.1`（cu121 末版） |
| 7 | C1 bundle 缺 cycles/*.npz（C2 前夕） | 打包函数漏列周期波形，服务器建库必失败 | 补 493 npz + 与 inventory 逐文件 sha 对照 |
| 8 | h103 CUDA 999 / h108 启动失败 / h102·h107 长期 down | 集群隐性故障，调度层不可见 | 探测脚本 + 报障单；作业 `-w h104` 钉定；`--extra` 透传机制 |
| 9 | C2 sbatch 自我冲突（C2） | 包装层预建 run 目录 vs 入口防覆盖守卫 | 环境捕获改暂存文件、训练后移入 |
| 10 | GPU 确定性训练崩溃（C3） | CUDA≥10.2 要求 `CUBLAS_WORKSPACE_CONFIG` | trainer 导入时 setdefault；sbatch 显式导出 |
| 11 | sacct 不可用致查询崩溃 | 集群未启用 accounting | 查询降级为仅 squeue + note |
| 12 | resume 后 best_epoch 归零（C3 后） | checkpoint 未存该字段 | 存 `_best_epoch` + 恢复函数单测 |
| 13 | 扩散时间嵌入设备不一致（D/E） | 频率张量固定 CPU | 跟随 `timesteps.device` |
| 14 | 扩散训练不收敛（noise_mse 恒 1.005） | 峰值尺度使信号 std≈0.13，对单位噪声信噪比过低 | 改 std 尺度，MSE 降至 0.77 且持续下降 |
| 15 | 扩散峰值越界（D/E 正式跑） | 欠训采样误差累积 + 截断阈值未换算坐标系 | 方法级峰值截断（按 power_scale 换算）；门独立复核不放宽 |
| 16 | prepare 在服务器必然失败（D/E 下游） | 固定枚举 test 分区而服务器永无 test shard | `--skip-test`；test 输入仍只在本地构建 |

**模式总结**：16 个问题里 9 个只有真实服务器环境才能暴露（设备、驱动、打包、
集群拓扑），这是 C1 冒烟阶梯"先校准厨房"策略的直接回报；所有修复均带回归测试
（测试数 136 → 194）。
